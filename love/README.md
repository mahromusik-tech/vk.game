# Вдвоём — live-игра «вопрос на двоих» для Telegram Mini App

Файлы: `index.html`, `style.css`, `app.js`, `supabase-setup.sql`.

## 1. Настройка Supabase

1. Откройте ваш проект → **SQL Editor** → New query.
2. Скопируйте туда содержимое `supabase-setup.sql` целиком и нажмите **Run**.
   Это создаст таблицы `players`, `couples`, `questions`, `game_sessions`,
   `answers`, включит RLS с открытыми политиками (см. ниже), включит Realtime
   и засеет банк из 50 вопросов.
3. Проверьте **Database → Replication**: таблицы `game_sessions`, `answers`,
   `players` должны быть включены в публикацию `supabase_realtime`
   (скрипт делает это автоматически).

URL и публичный ключ уже прописаны в `app.js`:
```js
const SUPABASE_URL = "https://dnkbkytudvhnglnluecc.supabase.co";
const SUPABASE_ANON_KEY = "sb_publishable_qXCffsva69vx26EmgR8SGg_ZaTa6mjh";
```
Это публичный (`anon`) ключ — его можно спокойно держать в клиентском коде,
он не даёт доступа к настройкам проекта, только к тем таблицам, для которых
разрешён RLS-политиками.

⚠️ **Про безопасность**: политики в скрипте открыты (`using (true)`) — это
нужно, чтобы приложение работало без отдельного сервера. Для тестовой игры на
двоих это нормально, но это значит, что теоретически кто угодно с вашим
ключом может читать/писать в эти таблицы. Если захотите закрыть доступ
жёстче — самый надёжный вариант: добавить Supabase Edge Function, которая
проверяет подпись `initData` Telegram, и провязать политики через неё.

## 2. Деплой на GitHub Pages

1. Создайте репозиторий, залейте туда все 3 файла (`index.html`, `style.css`, `app.js`) в корень (SQL-файл заливать необязательно).
2. Settings → Pages → Source: `Deploy from a branch`, ветка `main`, папка `/root`.
3. Через минуту приложение будет доступно по адресу вида
   `https://<ваш-логин>.github.io/<репозиторий>/`.

## 3. Подключение как Telegram Mini App

1. Напишите **@BotFather** → выберите вашего бота → **Bot Settings → Menu Button**
   (или `/newapp`, если хотите отдельное Mini App) → вставьте ссылку на GitHub Pages.
2. Откройте бота в Telegram и нажмите кнопку меню — приложение откроется внутри
   Telegram, автоматически считает `id`, `username` и `first_name` пользователя
   через `Telegram.WebApp.initDataUnsafe.user` и создаст запись в `players`.
3. Приложение также открывается в обычном браузере (для теста) — в этом
   случае оно создаёт «гостевой» идентификатор в `localStorage`.

## 4. Как это работает

- **Свой код**: у каждого игрока при первом входе генерируется уникальный
  6-символьный `game_code`, который показывается на главном экране.
- **Добавление партнёра**: партнёр вводит ваш код в поле «Код партнёра» →
  создаётся взаимная связь в `players.partner_id` и запись в `couples`.
  Если партнёр привязался со своей стороны, ваш экран обновится сам —
  это слушается через Supabase Realtime.
- **Начало игры**: любой из двоих жмёт «Начать игру» → создаётся
  `game_sessions` с 10 случайными ID вопросов из банка на 50 → второй игрок
  подхватывает это автоматически через Realtime и тоже переходит в игру.
- **Живые ответы**: каждый ответ — отдельная строка в `answers`. Как только
  оба ответа на текущий вопрос есть в базе, у обоих на экране появляется
  надпись «Следующий вопрос через мгновение…», и через 3 секунды
  `current_index` в сессии увеличивается — это тоже приходит по Realtime
  обоим одновременно, так что вопросы всегда синхронны.
- После 10-го вопроса сессия помечается `finished`, и на обоих экранах
  показывается финальный экран с кнопкой «Сыграть ещё раз».

## 5. Что можно доработать позже

- Проверка подписи Telegram `initData` на сервере (Edge Function) для
  настоящей безопасности вместо открытых RLS-политик.
- История прошлых игр / отдельный экран с ответами всех прошлых раундов.
- Возможность нескольких партнёров одновременно (сейчас — один активный
  партнёр за раз, для смены нужно сначала «Отвязать партнёра»).
